# Read-only planner and adapter seams

This phase adds a conservative planner, not a cleanup executor. `aps plan MANIFEST` defaults to KEEP with no evidence. `--execute` always returns a BLOCKED result and exit 1. Nothing removes, moves, chmods, quarantines, or notifies about artifacts. Only explicitly selected metadata/report outputs may be written by the CLI.

## Evidence and decisions

`aps schema planner-evidence` exports the version-1 schema. `--evidence FILE` uses a local file adapter; absent or unavailable evidence uses a null adapter. Snapshots are operator assertions, not authenticated provider state. They must supply task/host, producer, revision, manifest SHA-256, observation/expiry timestamps, terminal state/time, explicit approved root identities/owner/grace, complete reference/lease lists, complete mount topology claims, and protected/worktree paths. Unknown fields/values fail closed; malformed snapshots are errors, and incomplete/unavailable snapshots yield KEEP. Evidence reads reject symlinks, special files, and files larger than 2 MiB.

Manifest digests use SHA-256 of UTF-8 JSON with sorted keys, compact separators, and `ensure_ascii=False`. Evidence expires within five minutes; future, stale, inconsistent or rollback clocks retain artifacts. An optional event log must match task/host and the snapshot's terminal status/time. A newer completion or resumed event invalidates old terminal/grace evidence.

Only explicit regular-file artifacts strictly inside a separately approved registered root can be candidates. Root approval alone never grants execution. The planner checks root/file device/inode, current user ownership, root write permissions, single hardlink count, symlink ancestors/leaf, protected classes, non-disposable flags, references, leases (including expired claims), mount boundaries, and Git markers. A `.git` directory, file, or symlink is a protection marker; gitfiles are never read or followed. Bare-repository markers and worktree/scratch intersections also retain artifacts. Broad home/system/temp roots are refused.

Explicit protected/non-disposable manifest ancestors retain their descendants. Protection, reference, lease, mount and worktree comparisons combine literal overlap with no-follow device/inode and ancestor observations, preserving filesystem aliases without lowercasing distinct names. Unverified retained identities or reference/lease relationships mean KEEP. These observations are bound into the state digest, so replacing a referenced object invalidates a saved plan even when candidate totals are unchanged. This remains read-only observation, not atomic namespace containment.

Broad-root exclusions compare the selected directory itself with no-follow identities of existing forbidden physical directories and the configured home directory. A legitimate scratch child has a different identity and is not excluded just for being beneath home. Missing, linked or unverified home identity, or an unreadable broad-root identity, means KEEP before any root walk. Scope observations are also bound to the plan; forbidden directories are inspected as metadata only, never recursively scanned by this guard.

Root scans reuse the descriptor-relative telemetry walker, bounded to 10,000 entries and depth 64 per approved root. Incomplete scans, symlinks, special files, and observed device boundaries retain the root's candidates. Reference/lease snapshots and complete mount/worktree claims remain assertions from the selected file, not independent proof. Same-device mounts and concurrent namespace movement cannot be ruled out authoritatively by this implementation.

Grace runs from the latest terminal, manifest update, artifact record, filesystem modification, or inode-change time. Writes after the evidence snapshot and future filesystem times retain the file. File sizes, allocated blocks, and capacity deltas remain different quantities. Removed count/bytes are zero; reclaimed-by-task is unknown (`null`) in planner/task-end output.

Plans contain deterministic KEEP/WOULD_REMOVE reasons, evidence basis/revision/digest, manifest/state digests, audit entries, and a `plan_digest` over the full unredacted payload excluding that digest field. `planner.revalidate_plan` verifies payload consistency, timestamps and complete canonical semantic content against a fresh recomputation from evidence/current filesystem state. Changed decisions, totals, reasons, bindings or unknown fields are refused even if an edited payload has a recalculated digest. JSON types remain distinct (for example, `true` is not integer `1`). Valid receipt timestamps may differ from the fresh observation, but must be coherent and within the five-minute planning window.

Changed evidence/revision, references, leases, events, metadata, root state or decisions invalidate the previous plan. Event-backed revalidation must supply the current event list; omission invalidates the original event-bound state. Reports linking a plan also require fresh matching evidence through `evidence_adapter` and current events; omitting the adapter uses the conservative null adapter. Public display copies cannot be revalidated as private input plans. Digests detect consistency changes, not authorship or authorization; revalidation never enables execution.

## Task-end flow and privacy

`aps task-end MANIFEST --events EVENTS.jsonl [--evidence FILE] [--format json|markdown] [--public] [--output NEW_FILE]` links a plan to the existing Scoop Report. Planner KEEP decisions constrain eligible accounting. The null notification adapter returns `not_attempted`; no desktop banner is requested or assumed. This is an explicit file-event command, not a subscribed/live lifecycle integration.

Public planner/task-end copies hide entire absolute paths, filenames, host/task/producer identities, revisions and audit subjects. General public reports retain registered-root-relative names as documented for Phase 1, but use a safe whole-field fallback for unknown absolute/embedded paths. Public CLI diagnostics are generic on every error channel, including parsing; implicit option abbreviations are disabled. Metadata writes use anchored parent descriptors as described in [Phase 1](PHASE1.md).

`build_plan(public=True)` and `build_report(public=True)` also expose only generic `ValidationError` messages/fields on failure, without retaining the private validation exception as a chained context. Non-public callers retain detailed diagnostics. Task-end event files use the bounded regular/no-follow reader and limits documented in Phase 1.

## Why execution remains blocked

Every plan reports these unresolved gates: atomic identity-and-delete, complete platform mount containment, and authoritative live reference/lease evidence. `dir_fd`/no-follow plus `stat` is not atomic compare-and-delete, and an opened ancestor can move outside a root. Cooperative locks, missing PIDs, task completion, expired leases, age or access time alone do not prove disposability. There is no destructive fallback.

Real orchestrator lifecycle/reference adapters and desktop notification integrations remain BLOCKED until a stable authorized public interface and its authority are verified. No private provider configuration or machine-specific interface is embedded. Live cleanup, adversarial macOS containment, APFS clone/snapshot/open-file reclamation, crash receipts and independent executor acceptance remain deferred.

## Research receipt (2026-11-01)

The selected approach reuses public-source research supplied for this phase; no upstream source or new dependency was copied or installed. Agent Reach CLI was unavailable (exit 127); research used official GitHub search/API. The sources below are pattern evidence, not adopted dependencies or security clearance.

- [systemd-tmpfiles v262.1, `73612ea502d53baf9b0df4336cfc296a7ee0d524`](https://github.com/systemd/systemd/blob/73612ea502d53baf9b0df4336cfc296a7ee0d524/src/tmpfiles/tmpfiles.c): the component SPDX/license is LGPL-2.1-or-later. C/systemd, Linux-specific APIs and build dependencies do not fit this macOS/stdlib core. Descriptor-relative observation, inode checks, mount skips and declarative exclusions informed the design; source and lock-error continuation were not copied. Maintenance evidence includes the Oct 2026 [FUSE exclusion issue and regression fix](https://github.com/systemd/systemd/issues/44435).
- [cargo-sweep v0.8.0, `82f42d3593923db6fe715b299036512d91ddb35e`](https://github.com/holmgr/cargo-sweep/blob/82f42d3593923db6fe715b299036512d91ddb35e/src/fingerprint.rs): MIT component license, Rust/Cargo-specific implementation and twelve direct dependencies. Keep-set and unchanged-fixture dry-run test ideas are useful. Access time is not disposal authority ([issue 11](https://github.com/holmgr/cargo-sweep/issues/11)); attempted-byte accounting before removal is not verified removal. Platform CI includes macOS/Linux/Windows and the research observed May 2026 maintenance. No full transitive license/RustSec audit was performed, so adoption was not proposed.

The focused stdlib implementation avoids a new production dependency and LGPL source reuse, while retaining the maintenance burden of explicit schemas, conservative policy tests, and future platform containment work. Public advisory inventories were inspected by the research pass, but are incomplete evidence; upstream tests were not executed. The [CPython descriptor API](https://github.com/python/cpython/blob/v3.11.14/Doc/library/os.rst) and [mount detection limitations](https://github.com/python/cpython/blob/v3.11.14/Doc/library/os.path.rst) support keeping execution disabled. MIT project licensing is unchanged.

The alias comparison fix reuses the local descriptor-based observer and the above inode-checking pattern. [Apple's archived secure file guidance](https://developer.apple.com/library/archive/documentation/Security/Conceptual/SecureCodingGuide/Articles/RaceConditions.html), read on 2026-11-01, describes how filesystem case aliases defeat filename-only security checks. No upstream implementation was copied; case-sensitive names remain separate when their observed objects differ.
