# Safety model

Phase 1 implements observation, validation, and reporting only. The conditions below are necessary checks, not deletion authority. Phase 1 cannot satisfy all of them and never removes artifacts. A separate closed-store collector supports only newly created APS-broker files under the additional [managed execution contract](EXECUTION_SAFETY.md); it cannot execute an old manifest or adopt existing roots. Manifest operations write the explicitly selected metadata file; reports write only a new explicitly selected output file. A failed manifest write leaves its private staging file for inspection.

## Minimum conditions for automatic cleanup

ALL of the following must hold:

1. The target is inside an owner-approved, dedicated disposable scratch root.
2. A validated manifest records the producer task, host, artifact type, identity and explicit disposable classification.
3. The producer task is terminal, the retention period expired, and no other active, paused, resumable or dependent task holds a reference.
4. The executor rechecks the path and real file identity immediately before the operation, rejecting symlinks, unknown mount boundaries and changed inodes.
5. The action has sufficient scoped authorization and is logged with an auditable receipt.

Any unknown or failed check → retain the file. Completion status alone is never deletion authority.

## Closed managed-store authority

All participating producer reads, writes, references, leases, state transitions and resume generations use the same live APS broker. It creates opaque flat regular-file objects and never exports writable file descriptors or paths. The trusted owner approves the exact plan/object set/revision/operation; the producer socket cannot approve or collect. Null/file/native status snapshots never become a grant.

A process-wide physical-store mutex and fresh advisory lock remain held across durable retirement intent, unlink, namespace synchronization and durable finish. Pending or ambiguous effects block new producer operations until identity-bound owner reconciliation. IDs/tombstones are permanent; a missing object after a crash has unknown causality, and replay never double-counts prior effects. Expired leases remain protective until explicitly released.

This is a cooperative producer protocol, not kernel enforcement against raw same-UID writers, inherited access or outside-protocol namespace/mount changes. Mode 0700 and advisory locks do not close that gap. Stat plus unlink is not inode-conditional or ancestor-containment atomic. Power-loss/APFS reclamation guarantees and native-global AO/Kynlo lifecycle authority are unsupported. See the execution contract for platform exclusions, bounded inputs, recovery and capability-file commands.

## Protected data

Uncommitted files, Git worktrees, user-generated drafts, AI sessions and transcripts, local models, secrets, downloads, original media, virtual machines, shared caches and unknown directories are not eligible for automatic removal.

## Correct accounting

- Generated bytes: attributed to the task; may be estimated if writes outside registered roots are not observed.
- Candidate bytes: eligible file size, not guaranteed recoverable capacity.
- Removed bytes: only this invocation’s durable confirmed unlink receipts in managed collection; legacy reports remain zero. Partial, ambiguous and reconciled-missing outcomes never become invented successful removal.
- Reclaimed bytes: distinguish volume availability changes from causal task reclamation. Managed collection reports unknown (`null`), including after a confirmed unlink; legacy volume deltas are never attributed to the tool.
- Trash or quarantine does not necessarily release disk space.

Changes to cleanup eligibility require independent review and adversarial tests.
