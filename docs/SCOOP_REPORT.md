# Scoop Report contract

Phase 1 exposes this contract through manual `aps report` invocation. Automatic task-end delivery and notifications remain unimplemented. `eligible` means **dry-run candidates only**: the report lists unverified root approval, references, grace period, pre-action identity, and scoped authorization checks. No candidate is approved for deletion.

Every completed task should produce a report, even if no cleanup was possible:

- Task ID, host, timestamps and task status
- Generated bytes by class and the basis/confidence of attribution
- Retained bytes (source, drafts, active dependencies, etc.) and reasons
- Eligible bytes with verified task ownership and disposal classification
- Removed bytes, exact removal receipts and any errors
- Filesystem free capacity before and after, plus a qualified reclaimed-bytes estimate
- Skipped files, safety conflicts, missing metadata and grace-period holds
- Notification attempted/sent/verified status; no assumption that a banner was seen

Reports must not expose source code, tokens or private task transcripts. Redact personal paths in public copies. Suppress duplicate alerts without hiding task accounting.

Phase 1 measurements cover manifest-recorded regular files at report time, deduplicated by device/inode; they do not reconstruct historical writes or infer ownership of unrecorded files. Registered-root totals are contextual measurements and are not added to generated bytes. Unknown/skipped counts describe observations across artifact and root walks, so the same path can appear in both contexts. Capped detail lists preserve exact per-reason observation counts and indicate truncation. Retained reason totals may overlap when one artifact has multiple reasons.

Removed receipts are empty, removed bytes are zero, notification status is `not_attempted`, and reclaimed-by-this-tool is zero. Before/after capacity changes are reported separately and never attributed to this tool. Missing or unreadable measurements remain unknown rather than fabricated zero-byte measurements.

**Avoid misleading savings:** 3 GB removed from Trash, a hardlinked file, or a cloned APFS block may free less than 3 GB. Other processes may concurrently write data. Do not report exact reclaimed-by-this-task bytes unless causality is defensible.


## Unified managed report (version 1)

`aps managed report STORE --owner-key-file FILE --task-id TASK` reads the live owner's `accounting_snapshot` under one existing store fence. It never prepares/retires, approves, resumes, unlinks or notifies. It cannot accept edited receipt JSON or a legacy manifest as authority. An optional output is a new private file; public mode removes store/task/object/operation identities from the view.

The `agent-pooper-scooper/managed-report` schema joins:

- `generated`: historical broker-completed creation facts, including files later removed. `known_count` and `known_apparent_bytes` are verified lower bounds; absolute totals become null when creation history is incomplete. Never-created/pending/reconciled-missing creation tombstones do not become invented zero-byte creations. Allocated figures are recorded per-file metadata, not exclusive physical usage.
- `retained`: current verified-present registered files and protected/reference/lease/state reasons. Missing, changed or unverified presence remains unknown. This is a current observation, not a disposal grant. Eligibility is null/not evaluated; obtain a separate fresh managed plan.
- `removed`: cumulative confirmed identity/task/store/operation-bound retirement receipts, deduplicated by intent and artifact. Its count is the known confirmed subset, `known_bytes` is the verified lower bound, and `bytes` is null when disappearance/outcome evidence is uncertain. A report performs no new removals. The collector's per-invocation result and replay's zero new removals remain unchanged.
- `unknowns` and `audit`: bounded safe facts, exact reason counts and a revision-bound read-only ledger projection. Reporting writes no new ledger event. Partial or recovery-gated stores can be reported without authorizing effects.
- `reclaimed.bytes`: always null. Before/after free capacity is null/not measured here; a current sample is not reconstructed task-start capacity.

The complete report provides the existing notifier's `removed.count` and integer-or-null `removed.bytes`; the numeric projection does not copy private labels or audit subjects. Delivery remains explicit after the report fence exits. `notification.status=not_linked` means no task-bound delivery receipt was selected, not proof that a notification was never attempted; `integrations notice-status` reads its independently recorded operation classification. A native provider acknowledgement never establishes human visibility.

The legacy Phase 1 report's `removed` object has `allocated_bytes: 0`, empty receipts and errors; it is not a managed cleanup receipt and cannot be relabeled as one. The unified managed command is the supported full-report connection for actual broker collection.
